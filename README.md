# Movie Recommendation System

Проект рекомендательной системы фильмов на датасете MovieLens 100K. Система предсказывает оценки и выдает топ-10 рекомендаций для каждого пользователя.

## Данные

Используется классический датасет MovieLens 100K от GroupLens Research:
- 100 000 оценок фильмов
- 943 пользователя
- 1682 фильма
- Шкала оценок от 1 до 5

## Подход

Задача сформулирована как ранжирование. Положительным взаимодействием считается оценка 4 или 5 баллов.

Данные разбиваются по времени внутри каждого пользователя. Последние 20 процентов оценок идут в тест, остальные в обучение. Это позволяет избежать утечки информации из будущего.

## Реализованные алгоритмы

1. Popularity Baseline — рекомендует самые популярные фильмы с учетом истории просмотров пользователя
2. User-based Collaborative Filtering — находит похожих пользователей и рекомендует их любимые фильмы
3. Item-based Collaborative Filtering — ищет фильмы похожие на те, что понравились пользователю
4. Matrix Factorization через SVD — раскладывает матрицу оценок на латентные представления пользователей и фильмов

Для коллаборативной фильтрации используется cosine similarity.

## Метрики оценки

- Precision@10 — доля релевантных объектов среди рекомендованных
- Recall@10 — доля найденных релевантных объектов
- MAP@10 — средняя точность с учетом порядка рекомендаций  
- NDCG@10 — качество ранжирования с учетом позиций объектов

## Как запустить

Установите зависимости:
```bash
pip install pandas numpy matplotlib scikit-surprise
Откройте ноутбук и запустите все ячейки по порядку. Данные скачаются автоматически.
```

## Основные выводы

1. Проблема длинного хвоста. 
По данным хорошо видно, что со временем вкусы зрителей меняются. Сначала люди смотрят популярные хиты, а потом переходят на редкое нишевое кино. В тестовой выборке фильмы в среднем оказались менее популярными.

2. Почему популярность работает хорошо. 
Модели пытаются угадать редкие интересы, но им не хватает данных, поэтому они часто ошибаются. 
Попасть в точку с редким фильмом очень тяжело. А обычный бейзлайн работает грубо, но надежно, 
просто предлагая хиты, которые и так нравятся большинству.

3. Проблема самих метрик.
Алгоритмы из библиотеки surprise оптимизируют ошибку предсказания оценки, а не качество 
ранжирования. Модель может понять, что редкий артхаус понравится на 5 баллов, и поставить 
его на самый верх. Но в реальности человек вечером скорее выберет посмотреть знакомый блокбастер 
на 4 балла.

На практике же эти проблемы решают через каскад моделей. Процесс разбивают на несколько этапов, где на каждом шаге количество подходящих кандидатов постепенно сужается. 

Сначала простые и быстрые алгоритмы отбирают тысячи возможных фильмов из всего огромного каталога. Затем промежуточные фильтры сокращают этот объем до нескольких сотен. И только в самом конце тяжелая модель финально ранжирует этот короткий список. Она сводит вместе личные интересы пользователя и общую популярность контента, чтобы итоговые К рекомендаций выглядели максимально логично.
